# calendar-tui

Google カレンダーをターミナルで閲覧・編集する、Rust 製の TUI カレンダーです。
vim ライクなキー操作で月表示のカレンダーを移動し、予定の追加・編集・削除ができます。

## 特徴

- 月曜始まりの月表示グリッド（左）と、選択日の予定一覧サイドバー（右）
- 各日付セルに予定タイトルを箇条書きで表示（入りきらない分は `+N` で表示）
- 日本の祝日を自動で表示（赤色）
- 複数カレンダー対応。メイン以外のカレンダーの予定はマゼンタ色・`[カレンダー名]` 付きで表示
- 終日予定・時刻指定予定・複数日にまたがる予定に対応
- touch-server 経由のタッチ操作（タップで日付選択）に対応
- fbterm で表示崩れしやすい絵文字を安全な文字に置き換えて表示

## 必要なもの

- Rust ツールチェーン（edition 2021）
- Google Cloud の OAuth 2.0 クライアント ID（デスクトップアプリ）
- 幅 81 桁以上のターミナル（カレンダー 49 桁 + サイドバー 32 桁）

## セットアップ

### 1. OAuth クライアント ID を用意する

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成し、**Google Calendar API** を有効にする
2. 「認証情報」から **OAuth クライアント ID** を作成する（アプリケーションの種類は「デスクトップアプリ」）
3. JSON をダウンロードし、`credentials.json` という名前で次のいずれかに置く
   - カレントディレクトリ（`./credentials.json`）
   - `~/.config/calendar-tui/credentials.json`

`credentials.json` は `.gitignore` 済みです。コミットしないよう注意してください。

### 2. ビルドと起動

```sh
cargo build --release
./target/release/calendar-tui
```

初回起動時はブラウザが開き、Google アカウントでの認可を求められます。
認可が終わると `http://localhost:8080` にリダイレクトされ、トークンが
`~/.config/calendar-tui/token.json` に保存されます。以降はこのトークンを使い、期限切れの場合は自動でリフレッシュします。

> ブラウザが開かない環境では、ターミナルに表示される URL を手動で開いてください。
> 認可の待ち受けにポート 8080 を使うため、ほかのプロセスが使用していないことを確認してください。

## キー操作

### 通常モード

| キー | 動作 |
| --- | --- |
| `h` / `l` | 前日 / 翌日へ移動 |
| `k` / `j` | 前週 / 翌週へ移動 |
| `0` / `$` | 週の頭（月曜）/ 週末（日曜）へ移動 |
| `gg` / `G` | 月初 / 月末へ移動 |
| `[` / `]` | 前月 / 翌月へ移動 |
| `t` | 今日へ移動 |
| `o` | 選択日に予定を追加 |
| `c` | 選択日の予定を編集 |
| `d` | 選択日の予定を削除 |
| `q` / `Ctrl+C` | 終了 |
| `Ctrl+L` | 画面を再描画 |

### 予定の追加（`o`）

サイドバーに入力欄が表示され、4 ステップで入力します。各ステップで `Enter` で次へ、`Esc` で前のステップに戻ります。

1. **タイトル**
2. **開始時刻**（`HH:MM`）— 空欄なら終日予定になり、終了時刻の入力はスキップされます
3. **終了時刻**（`HH:MM`）— 空欄なら開始の 1 時間後
4. **終了日**（`YYYY-MM-DD` または `MM-DD`）— 空欄なら開始日と同じ日。`MM-DD` は今年の日付として扱います

### 予定の編集（`c`）

`j` / `k`（または `↑` / `↓`）で予定を選び、`Enter` で決定します。その後、次の順に入力します。各項目は現在の値が入った状態で始まり、`Esc` で前のステップに戻ります。

1. **タイトル**
2. **開始時刻**（`HH:MM`）— 空欄にすると終日予定になり、終了時刻の入力はスキップされます
3. **終了時刻**（`HH:MM`）— 空欄なら開始の 1 時間後
4. **終了日**（`YYYY-MM-DD` または `MM-DD`）

### 予定の削除（`d`）

`j` / `k` で予定を選び、`Enter` を押すと確認が出ます。`y` で削除、`n` / `Esc` でキャンセルします。

祝日は編集・削除の対象になりません。

## 設定

設定ファイルは `~/.config/calendar-tui/` に置きます。

| ファイル | 内容 |
| --- | --- |
| `credentials.json` | OAuth クライアント ID（カレントディレクトリにあればそちらを優先） |
| `token.json` | アクセストークン（自動生成） |
| `excluded_calendars.txt` | 表示しないカレンダー名の一覧 |

### カレンダーを非表示にする

`excluded_calendars.txt` に、表示したくないカレンダーの名前を 1 行に 1 つずつ書きます。`#` で始まる行はコメントとして無視されます。

```
# 表示しないカレンダー
誕生日
仕事（共有）
```

## タッチ操作

touch-server デーモン（`~/ssd/fb/touch/touch-server`）が起動していれば、Unix ソケット経由でタッチイベントを受け取り、タップした日付セルを選択できます。
接続できない場合はタッチ無しで通常どおり動作します。

ソケットのパスは次の順で決まります。

1. 環境変数 `TOUCH_SERVER_SOCK`
2. `$XDG_RUNTIME_DIR/touch-server.sock`
3. `/tmp/touch-server.sock`

タッチイベントは tmux のペイン単位で配信されるため、tmux の中で起動する必要があります。

## 端末環境についてのメモ

fbterm + uim-fep + tmux の構成で使うことを想定した対策が入っています。

- fbterm は U+FFFF を超える文字を表示できず、文字幅の扱いも ratatui と食い違うため、予定タイトル中の絵文字は置き換えて表示します（F1 カレンダーの 🏎 / ⏱ / 🏁 は「練」「予」「決」、その他の幅が合わない文字は「〓」）
- uim-fep の IME 切り替え（`Ctrl+Space`）で画面が乱れることがあるため、環境変数 `UIM_FEP_GETMODE` のモードファイルを監視し、切り替えを検知したら全画面を再描画します。乱れが残った場合は `Ctrl+L` で再描画できます
- 起動中やペーストで溜まった入力がコマンドとして実行されないよう、起動直後の入力は破棄し、ペーストされたテキストは無視します

## 既知の制限

- 予定の追加・編集・削除の対象はメインカレンダー（primary）のみです。ほかのカレンダーの予定は表示のみです
- 時刻指定の予定はタイムゾーン `Asia/Tokyo` で登録します
- アクセストークンは起動時にだけ取得します。起動したまま最長 1 時間ほど経つとトークンが切れて予定を取得できなくなるため、再起動してください

## ソース構成

| ファイル | 役割 |
| --- | --- |
| `src/main.rs` | ターミナルの初期化とイベントループ |
| `src/app.rs` | アプリの状態とキー・タッチ入力の処理 |
| `src/ui.rs` | ratatui による描画 |
| `src/calendar.rs` | Google Calendar API クライアント |
| `src/auth.rs` | OAuth 2.0 認証とトークン管理 |
| `src/config.rs` | 設定ディレクトリと非表示カレンダーの読み書き |
| `src/touch.rs` | touch-server クライアント |
